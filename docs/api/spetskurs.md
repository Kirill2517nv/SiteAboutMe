# Spetskurs API

Спецкурс по численному моделированию на C++ смонтирован на `/spetskurs/`
(`spetskurs/urls.py`) – **4 endpoint'а**, все публичные. Ни одного `POST`:
симуляция работает внутри iframe, а страницы только отдают данные.

Модель `CourseTask` связывает физику, исходник `main.cpp`, WASM-сборку и статьи
разбора. Сама теория живёт на моделях учебника (`Article(track='spetskurs')`),
поэтому ей достались та же типографика, MathJax и показ с проектора.

---

## Опубликованное и черновики

Разборы выпускаются по одной статье: пока `Article.is_published=False`, лендинг,
карточка задачи и страница задачи говорят «Разбор готовится», но симуляция
работает. Счётчик материалов на карточке считает **опубликованные** статьи тем
же `Prefetch`, что и список под ней (`_published_articles`) – обратная связь
`task.articles.count` фильтра публикации не знает и обещала бы «7 материалов»
у задачи, разбора которой на сайте нет.

## Endpoints

### GET `/spetskurs/` – Лендинг

**View:** `landing_view`
**Auth:** Не требуется
**Template:** `spetskurs/landing.html`

Карточки семестров собираются из тех же `CourseTask`, что и страница задач, –
лендинг не расходится с базой при переименовании задачи.

| Переменная | Описание |
|------------|----------|
| `semester1` | Задачи первого семестра |
| `projects` | Задачи второго семестра – работы прошлого года |
| `hero_sim` | Витрина в шапке (`Demo_Gravity`, `SimpleNamespace`, не запись в базе) |
| `hero_task` | Задача, из которой витрина выросла |
| `active_section` | `'landing'` |

!!! info "Почему витрина не в базе"
    `Task_3` – учебное задание, Луну вокруг планеты ученик дописывает в нём сам,
    поэтому у сайта своя сборка, где спутник уже есть. Отдельного `CourseTask`
    ей не заводят: он попал бы в список задач и в статистику.

---

### GET `/spetskurs/tasks/` – Список задач

**View:** `task_list_view`
**Auth:** Не требуется
**Template:** `spetskurs/task_list.html`

`CourseTask` с `is_published=True` и предзагруженными опубликованными статьями
(`to_attr='published_articles'`). Тот же `Prefetch`, что и на лендинге, – цифра
на карточке считается там же, где список под ней.

---

### GET `/spetskurs/task/<slug>/` – Задача

**View:** `task_detail_view`
**Auth:** Не требуется
**Template:** `spetskurs/task_detail.html`

`get_object_or_404(CourseTask, slug=slug, is_published=True)` – невыпущенная
задача отдаёт 404. Кадр симуляции получает задачу под именем `simulation`:
партиал общий с отдельной страницей симуляции.

| Переменная | Описание |
|------------|----------|
| `task` | Задача курса |
| `simulation` | Тот же объект – так его ждёт `_simulation_frame.html` |
| `articles` | Опубликованные статьи разбора этой задачи |
| `prev_task`, `next_task` | Соседи по списку опубликованных задач |
| `active_section` | `'tasks'` |

---

### GET `/spetskurs/basics/` – Основы C++

**View:** `basics_view`
**Auth:** Не требуется
**Template:** `spetskurs/basics.html`

Статьи трека `spetskurs`, не привязанные ни к одной задаче
(`course_task__isnull=True`): язык в объёме, нужном чтобы прочитать свой
`main.cpp`.

| Переменная | Описание |
|------------|----------|
| `articles` | Опубликованные статьи «Основ C++» |
| `active_section` | `'basics'` |

---

## Выпуск разборов

Публикация статей – не endpoint, а management-команда:

```bash
python manage.py publish_spetskurs <задача> [слаги статей]
```

Без слагов выходит весь разбор, со слагами – по одной вычитанной статье;
опечатка в слаге падает `CommandError`, а не тихо публикует ноль строк.
Проверка написанного – `python manage.py check_articles --track spetskurs`.
Порядок выкладки `.wasm` и архива исходников: `docs/spetskurs-deploy.md`.
