# Формат банка задач ЕГЭ

Спека JSON-файла для внешнего парсера. Такой файл загружается командой

```bash
python manage.py load_ege путь/к/файлу.json
```

и наполняет **банк задач** – тематическую подборку, из которой тренажёр собирает
сессии по номеру задания ЕГЭ. Тем же форматом (с другим `quiz_type`) грузятся и
готовые варианты; отличия перечислены в конце.

Живой образец: `fixtures/ege_bank_template.json`.

---

## 1. Общая структура

```json
{
  "quiz": { ... },
  "questions": [ { ... }, { ... } ]
}
```

Оба ключа обязательны, `questions` не может быть пустым. Кодировка файла –
**UTF-8 без BOM**. Весь импорт идёт в одной транзакции: любая ошибка валидации
откатывает файл целиком, полузагруженных подборок не бывает.

---

## 2. Объект `quiz`

Описывает контейнер подборки, а не задачу.

| Поле | Обязательно | Тип | Описание |
|---|---|---|---|
| `title` | **да** | строка | Название подборки. Видно только учителю в админке |
| `slug` | **да** | строка | Идентификатор подборки. **Должен быть стабильным** – по нему повторный импорт пополняет ту же подборку, а не создаёт новую |
| `quiz_type` | **да** | `"bank"` | Для банка всегда `"bank"` |
| `description` | нет | строка | Произвольное описание |

**`slug` – самое важное поле файла.** Он латиницей, без пробелов, в стиле
`bank-17`, `bank-17-slozhnye`, `bank-9-tablicy`. Если для одной и той же темы
парсер каждый раз сгенерирует новый slug, в базе будет расти по подборке
на каждый запуск.

Поля `exam_mode`, `is_public`, `max_attempts`, `start_date`, `end_date` для банка
**игнорируются** – их выставляет сама команда. Банк никто не решает целиком, у
него нет ни таймера, ни попыток.

При повторном импорте у существующей подборки обновляются только `title` и
`description`.

---

## 3. Объект задачи в `questions`

### Обязательный минимум

| Поле | Тип | Описание |
|---|---|---|
| `text` | строка | Условие задачи. Правила разметки – раздел 4 |

### Поля ЕГЭ

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `ege_number` | целое 1–27 | `null` | Номер задания ЕГЭ. **Без него задача не попадёт ни в одну тренировку по теме** и не будет учтена в статистике |
| `difficulty` | 1, 2 или 3 | `1` | 1 базовая, 2 повышенная, 3 высокая. Стартовое значение, см. раздел 6 |
| `external_id` | строка (≤64) | `""` | ID задачи на источнике. **Ключ дедупликации**, см. раздел 5 |
| `source_url` | URL | `""` | Ссылка на оригинал задачи |
| `points` | целое | `1` | Первичные баллы. Для заданий 26 и 27 – `2`, для остальных `1` |
| `topic` | строка (≤200) | `""` | Тема. Необязательно: группировка идёт по `ege_number` |
| `group_id` | строка (≤64) | `""` | Связка задач, см. раздел ниже |
| `group_order` | целое | `0` | Место в связке: `0`, `1`, `2` |
| `title` | строка (≤200) | `""` | Заголовок задачи. **См. предупреждение ниже** |

> **Предупреждение про `title`.** Если `title` пуст, заголовком становится
> **первая строка `text`, и она вырезается из условия** при показе. Для банка
> всегда задавайте `title` явно (`"Задание 17, вариант 42"`), иначе первая строка
> условия исчезнет с экрана.

### Связки задач (`group_id`, `group_order`)

Задания 19–21 – это одна игра и три вопроса к ней: условие описано в 19-м,
а 20-е и 21-е начинаются словами «Для игры, описанной в задании 19».
Разъединять их нельзя.

Задачи одной связки получают **общий `group_id`** и `group_order` `0`, `1`, `2`
в порядке 19 → 20 → 21:

```json
{ "ege_number": 19, "group_id": "kompege-19g-31365", "group_order": 0, "…": "…" },
{ "ege_number": 20, "group_id": "kompege-19g-31365", "group_order": 1, "…": "…" },
{ "ege_number": 21, "group_id": "kompege-19g-31365", "group_order": 2, "…": "…" }
```

Все три задачи идут в **одном файле банка** (`bank-19-21.json`, `quiz.slug`
`bank-19-21`): связка не может лежать в разных квизах.

Что делает тренажёр:

- любая отобранная задача связки тянет за собой всю связку по `group_order`,
  даже те её части, которые ученик уже решал (`ege_practice.expand_groups`);
- размер сессии режется **по целым связкам**: тренировка по 20-му на 6 задач –
  это две тройки, а не шесть двадцатых;
- в резерв под экзамен и в набор для урока задачи со связкой не попадают:
  флаг стоит на одной задаче, а выдаётся связка целиком, и помеченное 19-е
  утекло бы в тренировку вместе с 20-м (`mark_exam_pool`);
- статистика при этом обычная – каждая задача считается по своему `ege_number`.

Забыть эти поля – значит рассыпать банк на отдельные задачи: 20-е выдастся
со ссылкой на игру, которой ученик не видел.

### Тип задачи

| Поле | Тип | По умолчанию |
|---|---|---|
| `question_type` | `"text"` \| `"choice"` \| `"code"` | `"text"` |

Подавляющее большинство задач ЕГЭ – `"text"`: ученик вводит ответ строкой.
`"code"` используется там, где нужно прислать программу на проверку.
Актуальный список номеров живёт в `quizzes/ege_constants.EGE_CODE_TASKS`
и шире колонки «нужно спец. ПО» из спецификации ФИПИ: у нас программой
решаются и задания, где на экзамене вводится число. Для такой задачи нужен
`test_cases` – вывод программы сравнивается с ответом ЕГЭ:

```json
"question_type": "code",
"correct_text_answer": "98 293",
"test_cases": [{ "input_data": "", "output_data": "98 293" }]
```

Если эталон состоит **только из чисел**, сравниваются сами числа по порядку:
`98 293` в одну строку и те же два числа в две строки одинаково верны –
раскладка вывода не то, что проверяет задача. Порядок при этом важен, а вывод
с любым лишним текстом (`Ответ: 12`) сравнивается как обычная строка и не
засчитывается.
`load_ege` предупреждает, если `"code"` стоит на другом номере: обычно это
ошибка парсера, и ученик получает редактор кода вместо поля ответа.
`"choice"` в ЕГЭ почти не встречается.

### Поля для `question_type: "text"`

| Поле | Тип | Описание |
|---|---|---|
| `correct_text_answer` | строка (≤200) | Верный ответ |
| `alternative_answers` | список строк / `null` | Другие принимаемые формы ответа |

Ответ сравнивается **после нормализации**: приведение к нижнему регистру,
обрезка пробелов по краям и **срезание ведущих нулей**.

Из этого следуют два правила:

- `"42"`, `"042"` и `" 42 "` – это один и тот же ответ, дублировать их в
  `alternative_answers` не нужно;
- если верный ответ **сам начинается с нуля** (`"007"`, `"0110"` – двоичные
  записи, маски, коды), нормализация срежет нули и у ответа ученика тоже. Такие
  задачи проходят, но ученик, написавший `"110"` вместо `"0110"`, получит зачёт.
  Если это критично – не берите такие задачи в банк либо помечайте их для
  ручной проверки.

Разделитель в составных ответах берите **как на экзамене**: цифры подряд без
пробелов (`"3142"`) или числа через один пробел (`"128 4096"`).

Отдельно про **задание 27**: с 2027 года ответ – одна строка из двух чисел
(`"539936 100704"`), а не две строки по два числа, как было раньше. Частичный
балл (`ege_scoring`) считается по тому же правилу, что и в 26-м, и работает
только с двухчисленным эталоном.

### Поля для `question_type: "code"`

| Поле | Тип | Описание |
|---|---|---|
| `test_cases` | список объектов | Тесты, по которым проверяется программа |

Объект теста:

| Поле | Обязательно | Описание |
|---|---|---|
| `output_data` | **да** | Ожидаемый вывод |
| `input_data` | нет (`""`) | Данные на stdin |

Задача засчитывается, **только если пройдены все тесты**. Сравнение делает
`ege_scoring.outputs_match`: числовой эталон – по числам, любой другой – по
тексту после обрезки хвостовых пробелов и пустых краёв.

**Один ответ – один кейс.** Дублировать эталон в разной раскладке
(`"2508 104796"` и `"2508\n104796"`) незачем: раскладку чисел проверка и так
не смотрит, а лишний кейс на каждой отправке поднимает ещё один контейнер и
прогоняет решение по файлу данных заново. `load_ege` такие дубли отбрасывает
сам, и «одинаковым» считает ровно то, что таким сочла бы проверка.

Если задача читает данные из приложенного файла, а не со stdin, оставьте
`input_data` пустым и приложите файл через `files` – имя файла в коде ученика
должно совпадать с именем в условии.

### Поля для `question_type: "choice"`

| Поле | Тип | Описание |
|---|---|---|
| `choices` | список объектов | Варианты ответа |

Объект варианта: `text` (строка, обязательно), `is_correct` (bool, по умолчанию `false`).

### Вложения

```json
"images": [
  { "image": "ege/bank-17/images/17_1.png", "alt_text": "Схема дорог", "order": 0 }
],
"files": [
  { "file": "ege/bank-17/files/17_1.txt", "description": "Файл с данными", "order": 0 }
]
```

| Поле | Обязательно | Описание |
|---|---|---|
| `image` / `file` | **да** | Путь относительно `MEDIA_ROOT` |
| `alt_text` (только images) | нет | Подпись для доступности |
| `description` (только files) | нет | Подпись кнопки скачивания |
| `order` | нет | Порядок; по умолчанию – порядок в списке |

**Сами файлы должны лежать в `MEDIA_ROOT` до запуска импорта.** Команда не
скачивает ничего из интернета: она только переносит уже лежащие файлы в
канонический путь `ege/<slug>/images/` и `ege/<slug>/files/`. Если файла по
указанному пути нет, задача создастся, а вложение будет битым.

Рекомендуемый порядок работы парсера: сложить скачанные медиа сразу в
`media/ege/<slug>/images|files/` и указать в JSON этот же путь.

## 4. Разметка условия в `text`

Текст **не** является ни HTML, ни Markdown. Любые теги будут экранированы и
показаны как текст. Поддерживается ровно четыре вещи:

| Что нужно | Как записать |
|---|---|
| Новый абзац | Пустая строка |
| Перенос строки внутри абзаца | Одиночный `\n` |
| Таблица | Строки, где ячейки разделены **табуляцией** `\t`. Первая строка – шапка, первый столбец – заголовки строк |
| Картинка в нужном месте текста | `[img:1]`, `[img:2]` – номер картинки из массива `images`, **нумерация с единицы** |
| Верхний индекс | `[sup:10]` → 2[sup:10] |
| Нижний индекс | `[sub:2]` → A[sub:2] |

Пример условия с таблицей и картинкой:

```
На числовой прямой даны два отрезка.

[img:1]

Пункт	A	B	C
A		3	
B	3		5
C		5	

Определите длину кратчайшего пути.
```

**Если в `text` нет ни одного `[img:N]`,** все картинки задачи выводятся подряд
после условия. Как только появился хотя бы один маркер, автоматический вывод
отключается – расставьте маркеры для **всех** картинок, иначе часть пропадёт.

Степени и индексы из формул источника обязательно переводите в `[sup:]`/`[sub:]`:
`2^10` в исходном HTML это `2<sup>10</sup>`, и без конвертации ученик увидит
`210`.

**Маркер не бывает пустым.** `a<sub>0</sub>` это `a[sub:0]`, а не `a0[sub:]`:
пустой маркер рендер не ловит и показывает как есть – в задании 12 вся таблица
МТ читалась как «q0[sub:]». `load_ege` чинит такой текст на импорте
(`fix_empty_sub_markers`), но чинит по догадке «цифры перед маркером и есть
индекс» – правильнее не ломать.

## 5. Дедупликация: зачем нужен `external_id`

При импорте команда ищет задачу с таким же `external_id` **среди всех задач
ЕГЭ в базе** – и в вариантах, и в других банках.

- **Нашла** → обновляет существующую задачу, новую не создаёт.
- **Не нашла** (или `external_id` пуст) → создаёт новую.

Отсюда два следствия:

1. **`external_id` пустой – дедупликации нет.** Каждый повторный импорт того же
   файла создаст полный комплект дублей. Заполняйте его всегда.
2. Одна и та же задача, приехавшая и в составе варианта, и в тематической
   подборке, останется в базе в одном экземпляре.

Значение – любая строка до 64 символов, лишь бы она была **стабильной между
запусками парсера**. Годится ID задачи на источнике, при его отсутствии –
хеш условия. Не годится порядковый номер в файле или что-либо, зависящее от
даты парсинга.

Префикс источника делает id читаемым и защищает от коллизий, если позже
появится второй источник: `"kompege-17-000042"`.

### Что происходит с уже решавшейся задачей

Если по задаче есть ответы учеников (`UserAnswer`, `PracticeItem` или отправка
кода), при обновлении меняются **только текстовые поля**: условие, ответ,
сложность, баллы. Картинки, файлы, варианты ответа и тесты остаются прежними –
удалять их каскадом вместе с ответами учеников команда не станет.

В отчёте такие задачи считаются отдельно:

```
Банк задач "Банк задач: задание 17" загружен (slug=bank-17):
создано 12, обновлено 30, 4 обновлено без вложений (есть ответы учеников).
```

Если вложения такой задачи действительно нужно заменить, это делается вручную
через админку.

## 5.1. Пополнение банка: файл может содержать одну задачу

Импорт **добавляет и обновляет, но никогда не удаляет**. Задачи, которых нет в
файле, остаются в подборке нетронутыми.

Поэтому чтобы добавить одну новую задачу в банк из сотни, не нужно перепарсивать
всю тему. Достаточно файла с тем же `slug` и одной задачей внутри:

```json
{
  "quiz": { "title": "Банк задач: задание 17", "slug": "bank-17", "quiz_type": "bank" },
  "questions": [
    {
      "ege_number": 17,
      "title": "Задание 17, вариант 99",
      "text": "…",
      "question_type": "text",
      "external_id": "kompege-17-000099",
      "correct_text_answer": "777"
    }
  ]
}
```

```
Банк задач "Банк задач: задание 17" загружен (slug=bank-17):
создано 1, обновлено 0. Всего в квизе 3 задач.
```

Было две задачи – стало три. Обе прежние на месте.

Из этого следует удобный режим работы парсера: **инкрементальная выгрузка**.
Не отдавать каждый раз всю тему, а выгружать только то, что появилось на
источнике с прошлого запуска. Единственное требование – тот же `slug` и
стабильные `external_id`.

Обратная сторона: **удалить задачу из банка импортом нельзя.** Если задача с
источника оказалась битой, её убирают через админку (фильтр по `ege_number`
или поиск по `external_id`) либо командой `retag_ege` из раздела 5.2.

## 5.2. Смена кодификатора: тема переехала на другой номер

ФИПИ пересматривает КИМ, и содержание номера меняется. Данные о задании лежат
в трёх независимых местах, и обновлять их надо все три:

| Слой | Что там | Чем чинится |
|---|---|---|
| Справочник заданий | название и описание задания 1–27 | правка `EGE_TASKS` + `seed_ege_tasks --force` |
| Статья теории | разбор задания | переписать `seed_ege_theory_<N>.py` |
| **Задачи в банках** | `Question.ege_number` | **`retag_ege`** |

Третий слой – главный. Пока `ege_number` старый, тренировка по заданию будет
выдавать задачи снятой темы, а прогноз балла считать их за актуальные.

### Порядок действий

**1. Посмотреть, что затронуто.** `--dry-run` ничего не меняет:

```bash
python manage.py retag_ege --from 2 --to 5 --dry-run
```

```
Задач с номером 2: 143
     120  Банк задач: задание 2
      23  ЕГЭ Информатика – Вариант 4
Ответов учеников по ним: 512

[dry-run] Действие: перевесить на задание 5. Ничего не изменено.
```

**2. Выбрать одно из трёх действий:**

```bash
# тема просто переехала на другой номер – задачи и статистика сохраняются
python manage.py retag_ege --from 2 --to 5

# тема ушла из экзамена, но историю жаль – задачи уезжают в служебный квиз
# и перестают попадать в тренировки, ответы учеников остаются в базе
python manage.py retag_ege --from 2 --archive

# тема ушла, задачи не нужны совсем – удаляются вместе с ответами
python manage.py retag_ege --from 2 --delete
```

Архивация работает без всяких флагов «архивности»: задачи переезжают в квиз с
`quiz_type='standard'`, а отбор в сессию берёт только `'bank'`
(`PRACTICE_QUIZ_TYPES`).

Задачи внутри собранных вариантов (`quiz_type='exam'`) в тренировку не попадают
вообще: вариант пишется целиком и живёт своей вкладкой. Поэтому банк по каждому
заданию нужен свой – без него тренировка по номеру будет пустой, даже если этот
номер есть в десятке загруженных вариантов.

**3. Поправить справочник.** В `EGE_TASKS`
(`textbook/management/commands/seed_ege_tasks.py`) изменить название и описание
задания, затем:

```bash
python manage.py seed_ege_tasks --force
```

Без `--force` уже заполненное описание не перезапишется – по умолчанию команда
бережёт правки, сделанные в админке.

Slug статьи теории останется от старой темы (`ege-2-tablitsy-istinnosti`).
Это не ошибка: менять slug – значит ломать сохранённые ссылки. Если тема ушла
совсем, статью проще снять с публикации в админке и написать новую.

**4. Загрузить новый банк на тот же номер.** Обычный импорт, `ege_number`
прежний – номер задания в КИМ не изменился, изменилось его содержание:

```json
{
  "quiz": { "title": "Банк задач: задание 2 (графы)", "slug": "bank-2-grafy", "quiz_type": "bank" },
  "questions": [
    { "ege_number": 2, "title": "Задание 2, вариант 1", "text": "…",
      "external_id": "kompege-2-100001", "correct_text_answer": "57" }
  ]
}
```

Новый `slug` брать не обязательно, но удобно: старый `bank-2` после архивации
остаётся пустым, и отдельная подборка `bank-2-grafy` яснее говорит, что внутри.

`external_id` новых задач должен отличаться от архивных. Специально следить за
этим не нужно – ID на источнике у новых задач и так свои. Технически совпадение
даже безопасно: дедупликация ищет только среди действующих задач, архивные в
неё не попадают, так что новая задача создастся, а не перезапишет архивную.

После этого шага номер 2 живёт новой темой: тренировка выдаёт задачи на графы,
точность считается с нуля, прогноз балла учитывает только их.

### Чего команда сделать не может

- **Разделить тему.** Если задание 2 распалось на два новых, `retag_ege`
  перевесит все задачи скопом. Разделять придётся руками через админку
  (фильтр по `ege_number`) или загрузив задачи новым банком.
- **Откатить слияние.** Если на целевом номере уже были свои задачи, после
  переноса «свои» и «переехавшие» ничем не отличаются, и обратный `retag_ege`
  вернёт назад и те, и другие. Команда предупреждает об этом в `--dry-run`;
  перед переносом на непустой номер имеет смысл сделать дамп базы.
- **Сохранить статистику по старой теме в прогнозе.** И это правильно: после
  `--archive` номер начинает жизнь с чистого листа. Точность, прогноз балла и
  пул ошибок считаются только по действующим задачам, а история по снятой теме
  остаётся в базе, но в цифры номера не подмешивается.

## 6. Про `difficulty`: это только стартовое значение

Сложность из файла работает, пока по задаче мало статистики. Дальше команда
`recalc_ege_difficulty` (раз в сутки) считает долю учеников, решивших задачу
**с первой попытки**, и записывает её в `solve_rate`. С этого момента тренажёр
показывает уровень по факту, а разметка источника перестаёт учитываться:

| Доля решивших с первой попытки | Показываемый уровень |
|---|---|
| ≥ 0.7 | базовая |
| 0.4 – 0.69 | повышенная |
| < 0.4 | высокая |

Поэтому не тратьте силы на выверенную оценку сложности при парсинге. Достаточно
грубого правила: если источник даёт свою метку – переносите её, если нет –
ставьте `1` для заданий 1–16 и `2` для 17–27.

## 8. Валидация: на чём импорт упадёт

| Ошибка | Сообщение |
|---|---|
| Нет ключа `quiz` или `questions` | `JSON должен содержать ключи "quiz" и "questions"` |
| Пустой `quiz.title` | `Поле quiz.title обязательно` |
| `quiz_type` не `exam` и не `bank` | `Поле quiz.quiz_type должно быть "exam" или "bank"` |
| Банк без `slug` | `Для банка задач обязателен явный quiz.slug` |
| Пустой список задач | `Список вопросов пуст` |
| Неизвестный `question_type` | `Вопрос #N: неизвестный тип "..."` |
| `ege_number` вне 1–27 | `Вопрос #N: ege_number должен быть от 1 до 27` |
| `difficulty` не 1/2/3 | `Вопрос #N: difficulty должен быть 1, 2 или 3` |
| `slug` занят вариантом (не банком) | `Вариант с slug "..." уже существует` |

Номер задачи в сообщении – её порядковый номер в массиве `questions`, начиная
с единицы.

## 9. Отличия файла варианта

Тот же формат, три отличия:

| | Банк | Вариант |
|---|---|---|
| `quiz.quiz_type` | `"bank"` | `"exam"` |
| `quiz.exam_mode` | игнорируется | **обязателен**: `"exam"` (таймер, одна попытка) или `"practice"` |
| `quiz.slug` | обязателен | можно не задавать – выведется из `ID: NNNN` в описании или сгенерируется |
| Повторный импорт | пополняет подборку | **запрещён**: команда откажется, если slug занят |

Вариант дополнительно принимает `max_attempts`, `is_public`, `start_date`,
`end_date`. Образец – `fixtures/ege_template.json`.

## 10. Чек-лист парсера

- [ ] UTF-8 без BOM, `"quiz"` и `"questions"` на месте
- [ ] `slug` стабилен между запусками, латиницей
- [ ] У **каждой** задачи заполнен `external_id`, стабильный между запусками
- [ ] У каждой задачи заполнены `ege_number` и `title`
- [ ] HTML из источника переведён в разметку раздела 4: таблицы в `\t`,
      `<sup>`/`<sub>` в `[sup:]`/`[sub:]`, теги вычищены
- [ ] Если в `text` есть хоть один `[img:N]` – маркеры расставлены для всех картинок
- [ ] Медиа скачаны в `media/ege/<slug>/images|files/`, пути в JSON совпадают
- [ ] `points` = 2 для заданий 26 и 27, иначе 1
- [ ] У `text`-задач заполнен `correct_text_answer` в экзаменационном формате
- [ ] У `code`-задач есть хотя бы один `test_cases`
- [ ] Пробный прогон: импорт дважды подряд даёт «создано N, обновлено N»,
      а не «создано N, создано N»
